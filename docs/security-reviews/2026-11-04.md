Source evidence is [app.ts](https://github.com/floydnant/release-maestro/blob/cf97c1fbdc729b44191f5f07a65a419d10351a36/apps/maestro-electron/src/app/app.ts) and [app.events.ts](https://github.com/floydnant/release-maestro/blob/cf97c1fbdc729b44191f5f07a65a419d10351a36/apps/maestro-electron/src/app/events/app.events.ts). [Electron security guidance](https://www.electronjs.org/docs/latest/tutorial/security) recommends isolation, sandboxing and sender validation. The accompanying fix shares the navigation HTTP/HTTPS opener with IPC. Full mitigation still requires the preload, sender validation and media-policy design in [MAE-167](https://linear.app/floyd-haremsa/issue/MAE-167/harden-electron-renderer-isolation-and-ipc-access). ## Exposure and coverage gaps

The sole app use of `bandcamp-fetch` is `band.getInfo` in `bandcamp-api.backend.service.ts`; album scraping uses fetch plus Cheerio and validates tralbum data. Inspected bandcamp-fetch 3.2.1 `BandAPI.getInfo` uses ordinary fetch without `requireCookie`; its Fetcher defaults that flag to false. CookieFetcher launches Puppeteer only for cookie-required requests and does not pass `--no-sandbox`. No app executable-path override was found. This is evidence against browser launch through the inspected getInfo path, not proof that Puppeteer never runs or ships. Custom environment/cache executable selection and packaged dependency pruning remain unverified. Do not mark all Puppeteer CVEs not affected from this trace.

The Rust metadata sidecar directly parses local audio tags and embedded pictures with Lofty 0.25.5. Malformed imported files reach this parser; a sidecar process is not evidence of an OS sandbox. Fresh Cargo OSV coverage found no blocking advisory, only paste 1.0.15 RUSTSEC-2024-0436 maintenance information. Parser fuzz coverage and embedded/native binary inventories are not established by this scan. Electron and better-sqlite3 native dependencies also need artifact-level evidence.

CI uses pinned actions and the immutable release SHA for publication builds. Remediation reads Dependabot lockfiles without executing their code, installs with scripts disabled, and creates its write token after verification. PR vulnerability comparison uses an empty suppressions config and fails on scanner errors. Full/release scans remain the control for existing findings. This inspection did not attest hosted runner isolation or repository secret/ruleset settings.
